# R1863: print progress and administrator error follow-up

The print manager now updates the original overall progress bar during file transfer. Transient transfer percentages are weighted by original bytes, capped below verified completion, and reset for a new draft. Confirmed originals retain their contribution after refresh/retry. Verification and order submission remain separate; 100% requires the existing submitted state. No additional upload actions/panels are introduced.

The daily error dashboard presents one row per affected order, or per telemetry session when no order exists. Verified file-to-order ownership takes precedence over the mutable browser session's last order. Repeated per-file attempts remain available in collapsed technical details. The dashboard shows recorded originals, server-verified originals, and unverified originals, plus final order status. These are recorded server counts, not a promise that all browser selections reached the server. Successful sends remain one row per order. Reports are bounded and paginated with Tehran calendar boundaries.

Existing platform-admin-only reports now include photographer mobile and the oldest active laboratory administrator's mobile. All names/phone data use textContent. The SMS composer offers an editable default apology/resolution message. Opening it does not send anything. Only an explicit submit calls the new platform-admin-only endpoint. Recipient numbers are resolved server-side from the selected known laboratory/photographer; a submitted arbitrary mobile is never used. No customer or laboratory wallet charge is requested. Existing SMS provider configuration and SMS logging are reused, without changing R1852 administrator alert deduplication or budgets.

Every follow-up request has a UUID. A transaction, advisory lock and an existing sms_delivery_log reservation commit before contacting the SMS provider. Duplicate requests cannot dispatch twice, including across processes or a DB failure after provider acceptance. Ambiguous responses require checking existing SMS delivery logs; there is no automatic resend. Requests are limited to one per recipient per five minutes and twenty per administrator per hour. Provider acceptance is explicitly not presented as confirmed delivery. No real SMS was sent during tests.

No database migration, photo mutation/deletion, authentication mechanism, pricing/invoice, laboratory download or order-submission logic changes. New code is copied into dist by the existing build pipeline. Revert this PR and rebuild for rollback; previously recorded SMS claims/logs remain audit records.

Validation: production build, existing print recovery/browser/API/PostgreSQL and R1852 SMS regressions; new real-PostgreSQL tests for batch attribution/counts, lab/photographer isolation, pagination, concurrent duplicate SMS, conflict/rate limits, uncertain provider response, and DB interruption after provider acceptance. Browser tests cover editable explicit send, double click prevention, safe name rendering, phone display, grouped counts at desktop/mobile widths, and real print component progress before the send promise resolves. Release CI runs these checks.

Release gate: AGENTS.md prohibits automatic merging of security-sensitive changes. This PR introduces an administrator SMS endpoint and private contact fields, so leave it ready for review after green checks; obtain approval before merge/Auto Deploy. No manual deployment.
