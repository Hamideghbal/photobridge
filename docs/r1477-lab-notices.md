# R1477: native sound defaults, one alarm owner, subscription reminders

Windows 1.0.37 initializes each account's alarm settings once. Missing, silent or zero-volume legacy settings become gentle at a nonzero volume; existing repeat settings remain. A migration marker preserves later operator choices, including silence. Fresh installs default to gentle already; this also repairs persisted legacy settings.

The existing authenticated native heartbeat owns lab browser alarms. The browser checks every five seconds, disables its sound setting, prevents order popup/sound and chat chimes while the native owner is live, and explains the disabled setting. Server Web Push is also suppressed for labs while the native owner heartbeat is current (35-second lease). Closing the native program releases live popup/push ownership after lease expiry; the browser sound toggle remains off until manually enabled. This uses the existing process-local heartbeat store, so it assumes the current single API instance; multi-instance deployment would require a shared lease.

A persistent on-screen notice appears from 72 hours before the existing active_until timestamp and links to /lab/settings/subscription. It remains on expiry, displays the existing new-work restriction and disappears on renewal. No subscription deadline, payment logic or manual activation override is changed. Status comes from authenticated write-access; no early deactivation or extra three-day grace period is introduced.

A server worker runs at startup and every 15 minutes, even without any user logged in. For active, unsuspended, non-service labs it sends the earliest active lab-admin manager one reminder for each remaining 3/2/1-day bucket, then one expired notice within 24 hours of expiry. Long-expired accounts are excluded to avoid a rollout blast. Existing expiry enforcement blocks new writes while history and renewal remain available. The worker does not change labs.active. Successful renewal moves the deadline and cancels stale messages after a row-lock recheck.

SMS uses the platform gateway without charging the lab service wallet. Durable atomic claims in existing platform_settings prevent duplicate delivery across workers/restarts. Known pre-send missing/unsupported gateway errors retry next tick; ambiguous provider failures or crashes remain failed/dispatching and are not automatically resent (provider idempotency is unavailable). Existing sms_logs and per-claim statuses retain operational results. No production SMS was sent during development.

Validation: 100 native tests, seven targeted policy/worker/UI tests, final late-build snapshot/freshness/wire-byte/phone regression stages. SMS provider, PostgreSQL integration, actual browser rendering and Windows packaging/installation remain untested here. Native default migration needs the newly built 1.0.37 executable; website-only update does not replace native code. Preserve the existing publisher key and publish EXE with its matching JSON after server deployment.
