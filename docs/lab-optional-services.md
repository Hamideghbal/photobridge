# Lab optional services and invoice SMS (R1367)

The platform-admin lab row has independent Windows download and website grants. Explicit administrator grants take effect independently of subscription payment. A lab cannot grant itself either service. Self-service site requests still require the existing paid subscription flow; this does not prevent an admin from enabling an unpaid or expired account's site. Public domains continue to enforce active/non-suspended/full lab status and their existing domain verification. Disabling a grant revokes access without deleting domains, site content, orders or payment history.

General settings contains the dedicated-site and Windows-program entries. The obsolete Windows-alert tab and quick-access entry are removed. Legacy `/lab/settings/windowsAlert` links open the Windows-program page. Actual persistent native order alarms are unchanged. Downloads use the existing admin-uploaded EXE; no new Windows installer is produced here.

In the manual photo/album form, the inline SMS checkbox records a preference for the **current order**. Checking it sends nothing, including no invitation or older invoice. It is available for pending and complete members before they have an invoice. On successful submission its boolean is recorded in the order transaction. A rollback records no consent. Replayed submissions cannot schedule a duplicate SMS.

Migration `191_lab_intake_invoice_sms.sql` adds the order-scoped durable state. Existing orders remain opted out. Only an explicitly checked, successfully submitted order is eligible. The dispatcher sends its matching issued invoice to that order's customer's stored mobile, using the normal lab SMS service and wallet. It does not create an invoice, change pricing, issue proformas or change the existing ready-stage invoice timing. If no invoice exists yet, the request stays pending and a background worker checks every 30 seconds. Cancelled orders and other labs' invoices cannot trigger delivery. The old ready-status message does not additionally append invoice amounts for manually opted-in/out orders; ordinary status notifications retain their existing controls.

The atomic pending-to-dispatching claim prevents concurrent workers from sending twice. Sent and provider-failed attempts are not automatically retried, avoiding duplicate charges after an unknown provider result. Failures retain their error for manual review; a crashed in-flight attempt remains dispatching rather than claiming success. The submission result clearly distinguishes sent, pending, dispatching and failed. No actual SMS is sent during development tests.

Validation uses behavior tests plus optional PostgreSQL/PGlite suites for admin overrides, migration idempotence, same-order invoice selection, print/album delivery, rollback, unchecked choice, concurrency/replay, cancellation, tenant scope and provider failure. Full production/Windows/visual validation remains separate. AGENTS.md requires publication review for this schema and authorization change.
