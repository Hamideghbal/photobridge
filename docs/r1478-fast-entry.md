# R1478 / Windows 1.0.38: startup branding and faster entry

Native login previously awaited eleven sequential prime-cache requests and the entire Sync.run upload/pull cycle before returning the successful login response. It now keeps the same authenticated /auth/me lab-admin verification, persists the confirmed session, starts existing native alerts/update checks, resumes Sync and starts one background sync without awaiting its completion. The duplicate primeCache routine and duplicate startup cache fill are removed. No queue entries, caches or files are deleted; access enforcement and normal live UI reads remain unchanged. UI updates still complete their existing verification/activation before first login.

The native startup page uses the existing packaged PhotoBridge artwork at 240px, with a separate normal-flow caption, 20px gap and embedded project font. No external startup image/font request is needed. The existing mobile handoff mark is also slightly enlarged with explicit 24px spacing and normal-flow caption; embedded splash suppression remains.

The photographer lab-entry boot cover depended on labName() finding legacy header text even after the current print workspace was ready. The readiness predicate now checks the current print-mode navigation and populated scroll area, retaining chooser/unfinished-workspace guards and the existing stabilization timer. It no longer waits solely for an obsolete header label or the 5.2-second fallback. Full navigation and lab selection authorization remain unchanged.

Validation: 103 native tests, including actual onLogin extraction exercised with a deliberately stalled background sync, invalid-account rejection and self-contained startup-page structure. Three frontend tests execute both real settleBoot functions against ready/unfinished/chooser states and verify splash spacing. Final late-build snapshot/freshness/wire-byte/phone regressions pass. No real Windows startup timing, browser rendering or NSIS packaging was performed. Native performance changes need the built 1.0.38 EXE plus matching update JSON; shared frontend readiness/layout changes ship through the website UI.
