# Lab domains and installer delivery

R1373 preserves site editing before a domain is attached. Editor writes and public pages read `lab_public_site_content` by lab ID; connecting a domain does not create another content copy. Domain status appears in the dedicated-site settings card.

Enabled Lab sites can check a second-level ASCII `.ir`, `.com` or `.net` domain. Lookups use fixed registry hosts, not user-controlled URLs or DNS absence. IRNIC WHOIS is documented by IANA at https://www.iana.org/domains/root/db/.ir.html and exposed at https://whois.nic.ir/WHOIS?name=example.ir. Verisign RDAP is documented at https://www.verisign.com/news-insights/registration-data-access-protocol/help/ . Exact existing records are registered; explicit no-record responses are preliminary unregistered results. Timeout, rate limiting, unexpected payloads and service errors remain unknown. An unregistered result is not a guarantee of registration or a reservation.

`/api/lab/domain-requests/check` checks availability. `/api/lab/domain-requests` lists or creates requests scoped to the session lab and its site grant. Requests use existing `platform_settings` keys `lab_domain_request:<lab ID>:<domain>`, with at most 20 entries returned. No schema migration or domain purchase/payment is performed. Platform administrators review each lab's requests at `/api/admin/labs/<ID>/domain-requests`, marking reviewing/completed/rejected. Completion is a workflow label, not an automatic DNS connection. Existing domain ownership/verification and connection flows are unchanged.

Uploaded Lab installers are streamed through the existing authenticated and download-grant-protected installer route using the same S3 client as uploads and other server downloads. This avoids exposing the client to a separate presigned download-host redirect. Status verifies the object exists, ZIP/EXE filenames are retained, and HEAD/single byte ranges are supported. External configured fallback links retain their existing behavior. Previously uploaded objects are reused; no reupload or deletion is part of this change.

Local validation covers byte equality, headers/ranges/status/error cases, registry parsing/unknown results, roles/origin/scope/duplicates and actual PostgreSQL request persistence/review SQL. Production object download, registry connectivity from Liara and UI visual rendering require production verification.

## R1374: candidates, approved quotes, tax and payment

Only `.ir` and `.com` are accepted for new orders. If HTTPS registration lookup is unknown, try bounded direct WHOIS against the fixed IANA-listed registry host. An unavailable lookup never becomes a positive availability claim. Up to five distinct candidates can be checked or saved together. Saving candidates requires no successful network lookup and charges nothing; their state remains unverified pending review. A transaction and per-lab advisory lock enforce the 20-request limit without partially inserting a batch.

Iranserver's public reference on 2026-10-23 is 99,000 toman for one year of `.ir` and 3,375,000 toman for one year of `.com`, from https://www.iranserver.com/domains/tld/ . This is a dated estimate, not a live registrar quote or API integration. In the admin panel, verify the exact domain and final price with the supplier, enter its base amount and explicitly confirm availability. This creates a 24-hour quote with a fresh quote ID. No supplier-account credentials or purchasing API have been configured.

Per user instruction, quotes separately store/show 10% VAT: `taxAmount = round(baseAmount / 10)` and `amount = baseAmount + taxAmount`, in whole toman. For the reference prices, IR totals 108,900 toman and COM totals 3,712,500 toman. Provider reference prices are treated as the base for the platform's quote; the admin must confirm final base including any premium-domain/fee differences. No automatic repricing of accepted or paid orders.

The lab selects one or multiple quoted domains and explicitly pays their displayed total from the existing service wallet. The existing wallet page supplies its current top-up/payment flow. The backend validates every quote ID, expiry, amount and ownership; locks requests in sorted order and then locks the wallet. Wallet balance, one debit receipt per domain and paid-pending-registration state commit together. Insufficient balance, stale quotes or any failed debit roll everything back. Repeating the same paid quotes returns their receipts without charging again.

Admin completion requires prior payment on new orders. Admin rejection of a paid but uncompleted order refunds that domain's full amount including VAT to the same wallet exactly once, with a linked refund receipt. Completed domains cannot be rejected/refunded through this endpoint; no cancellation of a completed external purchase is implied. Existing older requests are explicitly distinguishable through absence of `billingRequired`. Domain purchase and DNS/ownership verification remain manual; paid does not mean registered or connected.

R1374 tests include real PostgreSQL SQL execution for tax totals, combined debit, idempotency, insufficient funds, expiry/stale scope, unpaid completion, refund replay, rollback after a failing second debit and atomic candidate limits. No real wallet was charged and no external domain was purchased during development.
